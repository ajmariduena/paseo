Git references, tracking and remotes during workspace handoff
Date: 2026-10-10
Baselines: 243b49962 (remote URLs), 7782ef99e (references/tracking).
Platform: Linux; real Git, temporary repositories, isolated daemon homes and WebSocket clients.

Behavior proved
- The initial URL regression lost origin. The reference regression then reproduced loss of
  non-HEAD branches, annotated tags, notes and symbolic remote refs. The tracking regression
  reproduced a restored branch with no upstream.
- Version 2 workspace manifests bind an explicit reference inventory to the bundle header,
  review and release. Restoration retains direct and symbolic refs, annotated/lightweight
  tags, blob tags and notes. An unborn HEAD can coexist with saved history; detached HEAD,
  SHA-256 and a branch sharing a name with a tag are covered. Direct refs install in one Git
  transaction. Legacy HEAD-only version 1 archives remain readable; unknown versions refuse.
- Named branch upstreams (including local upstreams), selected explicit fetch/pull/push policies,
  and fully qualified refspecs survive. Tests exercise an actual fetch with custom mapping and
  a negative branch pattern, followed by an actual push using a separate publication remote
  and configured refspec. These operations use local bare repositories through test-only URL
  rewrites; they make no external-network or authenticated-forge claim. An absent fetch mapping
  stays absent instead of receiving the default synthesized by git remote add.
- Stashes, replacement/custom namespaces, dangling/cyclic refs, URL-valued branch remotes,
  mirror policies and custom merge options refuse in preflight. Incoming mismatched/missing
  refs, symbolic cycles, unknown configuration keys and URL-valued branch remotes refuse
  publication. Ref and policy changes invalidate source review/release.
- Effective fetch/push destinations survive source insteadOf/pushInsteadOf rewrites, multiple
  URLs and distinct push targets. SSH login, port and exact path remain intact. HTTP userinfo,
  passwords, credential helpers, SSH commands and source rewrites are absent from installed
  configuration. Source credential rotation does not invalidate review. Destination URL
  verification permits host authentication rewrites. Unsupported remote forms and colliding
  names refuse before checkout creation; errors do not expose synthetic secret markers.
- The real two-daemon case checks the inventory in staging and after destination restart and
  activation, including symbolic origin/HEAD and the upstream/push configuration. Changing a
  tag, push policy or origin independently prevents release until the captured state is restored.

Execution notes
- The workspace file passed all 115 cases. Six cases covering reference installation, tracking,
  absent mappings, unborn/detached HEAD and legacy reading passed again after the private Git
  runner's optional arguments were consolidated into an options object. No full suite ran.
- The network case initially timed out at 30 seconds, including an isolated repeat. Temporary
  phase logging stopped between host startup and workspace creation, before any daemon Git
  command. The host globally enables SSH signatures for both commits and tags. Disabling only
  commit signing was insufficient. Isolating all fixture Git commands from global/system config
  removed the dependency; the case then passed in 2.97 seconds with the original timeout.
  Diagnostic phase writes were removed. No host Git configuration or main daemon was changed.
- Early failures also exposed a configuration-order-only test assumption and an outdated empty
  directory manifest version assertion. Assertions now compare cross-key configuration without
  ordering it, preserve within-key refspec order, and expect the new archive version. Malformed
  refspecs are validated before Git remote commands so errors carry no configuration value.
- Server-stack build, root typecheck and lint passed. No browser or provider continuation was
  exercised in this slice. Earlier remote-URL execution output is retained below.

Limits
- Reflog-only/unreachable history, remaining Git configuration, short/revision-expression
  refspecs, destination-global policy interactions and authenticated forge behavior still need
  evidence or dispositions. Unsupported stashes and custom refs require user resolution.
- Source SSH aliases and credentials are not transferred. Physical MacBook/VPS, native/mobile,
  Electron and version-drift gates remain open. Windows ownership release/activation remains
  unavailable pending directory durability.
- Complete handoff remains unadvertised and PR #30 remains a draft.
