Handoff real-provider app validation — Linux, 2026-10-09

Two browser cases use the real app, two isolated daemons, Git workspaces and Claude Code 2.1.295.
Each source and destination uses its own provider configuration directory. Existing authentication
is linked locally for the test; credentials and host settings are not part of the handoff archive.

Both cases review, prepare, activate, open the destination conversation and continue through the UI.
The source starts in bypass mode; destination Write requires approval through the app. A prior-only
token must be written to continued.txt in the destination, with no such file in the source. Source
prompts are refused after preparation and after destination continuation.
Native: the original user message is visible and the provider session ID remains the same.
Context export: the historical token is beyond the supplied excerpt; the new session reads exported
files and receives a different provider session ID. This run covers exported-file fidelity and a real
continued turn. The later destination history UI results are recorded in handoff-history.txt.
Actual MacBook/VPS, Electron, native iOS/Android and other provider evidence remain pending.
