Workspace review binding — 2026-10-09

Baseline: 012d3ef90 (cancellation recovery).

Coverage: Linux, real filesystem, isolated two-daemon RPCs and Chromium browser
flows. No provider turn or main daemon restart. This does not exercise the
physical MacBook/VPS pair, Electron, iOS, Android, macOS, Windows or released
version drift.

App review records the canonical source directory, included paths and file types,
executable modes, symlink targets, Git HEAD/index/normalization and the complete
collapsed omission list. Both journals retain that digest through restart. The
coordinator checks it before reserving a destination; the source checks before
fencing, during capture and before release. Ordinary working-file content edits
remain allowed before capture, so editor saves do not require another review.
Capture verification still binds their final bytes.

Tests cover changed ignore rules in Git and directory workspaces, same-count
included renames, omissions beyond the visible sample, retry identity and refusal
to release after omission changes. A changed review before reservation leaves
source work running and permits a fresh review.

The screenshot handoff-review-changed.png shows the re-review error and action
above the still-running synthetic terminal.

This binds only the workspace transfer boundary. Stopped-resource and integration
inventories still need review binding. Lower-level programmatic calls can omit
the review precondition; the app requires it. Protocol fields remain optional and
production daemons still do not advertise the unfinished feature.
