Handoff persistence recovery foundations — 2026-10-10

Two independently reproduced defects are fixed here. This is not the complete
conversation persistence barrier: runtime generations, semantic obligations,
provider callback quiescence and durable process-stop recovery remain open.

1. A rejected agent-record mutation previously rejected the next queued mutation
   without executing it. A regression now preserves the first caller's error and
   proves the following restart note survives reconstruction of AgentStorage.
2. A process restart could read a released ownership journal after rename but before
   successful directory synchronization. The source could then issue a receipt
   from that readable state. Recovery now synchronizes the existing file and its
   publication directories before admitting operations. Continued sync failure
   prevents receipts and source mutations; repaired storage recovers the same
   irrevocable binding without revalidating mutable source content.

The ownership test uses real file rename and an injected publication failure,
then reconstructs the owner. It does not simulate an actual power cut. Existing
Windows release restrictions remain; no cross-host/provider continuity claim.
