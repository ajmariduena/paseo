Handoff persistence recovery foundations — 2026-10-10

The complete conversation barrier remains open: pre-provider runtime generations,
revision guards, semantic obligations, callback quiescence and durable process-stop
recovery are not implemented by these changes.

Agent-record publication:
- Reproduced false acknowledgement in the cache after a successful rename followed
  by failed directory synchronization. Failed publication now retains one immutable
  candidate per agent, including its synchronization requirement. Later mutations
  complete that candidate before evaluating their own preconditions. The original
  caller still receives its failure.
- Reproduced snapshots observing later changes to a live agent's model and timestamp.
  Snapshot input is now captured at admission; record-owned fields merge in the queue.
- A failed closed-record write can be repaired through the strict handoff inventory
  and checkpoint without reopening the provider. The checkpoint returns the exact
  record validated by its serialized publication. This is same-process recovery;
  the retained candidate is not a restart-safe semantic obligation.
- Deletion waits for in-flight publication and removes a renamed file even when
  synchronization then fails. Windows rejects unsupported durable publication before
  retaining a candidate, so an unsupported checkpoint cannot poison ordinary writes.
  The Windows-only regression is skipped locally and awaits Windows CI.
- Current owning suite: 26 passed, 1 Windows-only case skipped. Full typecheck and lint
  pass; npm format completed. Tests use real temporary files, injected sync failure
  and reconstruction of AgentStorage, not a power cut or a provider session.

Earlier foundations, retained below:
- A rejected queue mutation no longer discards the following restart note.
- Ownership recovery synchronizes its existing journal before mutations or recovered
  receipts. A failed sync keeps the source fenced; repair retains the irrevocable
  binding without revalidating mutable source content. The earlier 42 POSIX and 12
  common ownership cases passed on 058e2be5f and were not rerun for this storage edit.
